How it works

A sealed engine. Replaceable knowledge. A written record of everything.

The engine is sealed

One static binary, no installer, no account, no telemetry, no network calls you didn't ask for. The Stasis you install today behaves identically in ten years. It never updates itself — an update firewall that auto-updated would be a joke at our own expense.

Recipes are data, not code

Everything about the changing world lives in recipes: signed, human-readable files describing one app's update machinery and how to silence it. A recipe compiles down to seven declarative actions — no scripting, no surprises. When Chrome rearranges its updater, a new recipe ships. The binary doesn't move.

Everything is journaled

Every change Stasis makes is written to an append-only journal with the exact undo data to reverse it — prior service state, prior registry value, where the updater executable went. stasis thaw restores your machine to its pre-Stasis state. Nothing is off the books.

Change becomes a ceremony

When you decide to update, you open the gate: snapshot first, pick exactly what moves, see the diff after, roll back if it broke. The gate can be scheduled — but it never opens itself.

The covenant

Printed in the box. Part of the license.

  1. Stasis never updates itself automatically. Ever.
  2. No network calls except two — both optional, both user-initiated. Fetching new recipes, and checking for signed security-only patches. Fully functional offline; recipes travel fine on a USB stick.
  3. No telemetry, no analytics, no account, no activation server. The license is a signed file, verified offline.
  4. No feature of v1 will ever be removed, moved, renamed, or paywalled. The v1 you buy is pixel-for-pixel the v1 running in 2036.
  5. Your data lives in open, documented formats. One folder. TOML, JSON, JSONL. Readable with a text editor; the format document ships in the box.
  6. Security fixes ship as signed, opt-in patches that change nothing but the flaw. Each with a one-page description of exactly what moved.
  7. If the company dies, the catalog outlives us. A pre-committed escrow releases the recipe-signing keys. Your binary already works forever without us.

Straight answers

The questions we'd ask too.

Is blocking updates safe?

Windows security patches stay ON by default — a machine silently missing security fixes is the one broken promise we refuse to ship. Freezing an app holds back its fixes too; that's your call to make, stated plainly once in the manual. We never nag.

How can an update-blocker survive a changing world without updating?

By separating behavior from knowledge. The engine's behavior is eternal; its knowledge of each vendor's updater is replaceable paper — signed recipe files you choose to install, or write yourself. The format is public.

What exists today?

The M1 engine is built and tested: scan, freeze, thaw, the journal, and a ten-recipe starter catalog (Chrome, Edge, Firefox, VS Code, Slack, Discord, Spotify, Zoom, Notepad++, GitHub Desktop). The terminal above shows its real output. Snapshot, gate, and rollback are next; then the seal.

Which platforms?

Windows 10 and 11 first — it's where forced updates hurt most and where twenty years of kiosk and POS freezing prove the buyer exists. Other platforms would be separate products under the same covenant, never a creeping v1 feature.
